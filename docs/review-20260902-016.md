## 方案（016 七意见逐条落实）

### 1. [测试成败判定] 仅成功登记
**落实**：拦截器在 next() 后观察工具结果（exec 结果含 exit code/isError）——`exit==0 && !isError` 才 audit `test-run`；失败/非零 → audit `test-fail`（拒绝提示中展示最近 test-fail）。

### 2. [bash 工具名实证] 已实证 = `bash`
**落实**：auto-approver 日志 179 条 `"toolName":"bash"` 实证（write/edit 已拦截）。拦截器条件：
```js
if (exec?.name !== 'bash' && exec?.name !== 'write' && exec?.name !== 'edit') return next()
```
测试含断言用例：模拟 exec.name='bash' 的 git push → 拦截触发（防挂错工具 fail-open）。

### 3. [sessionId + repo 归属] audit 补字段
**落实**：audit 记录 `{action:'test-run'|'gate-precheck', sessionId, repo: cwd}`（repo = 执行时的 cwd 或命令内路径）：
- 跨会话不共享：push 检查仅查**本 sessionId** 的 test-run 记录
- 仓库关联：push 的 repo（命令内 repo 路径或 cwd）须匹配 test-run 的 repo（同仓库测试才解锁）
- 读取策略：design-review.log **尾部窗口**（tail 最近 200 行解析，避免全量扫描）

### 4. [定位改写] 护栏+审计，非安全边界
**落实**：新增「定位与局限」节：
- 本关卡 = **流程护栏 + 审计问责层**（bash 命令字符串可绕：脚本包装/git -C/别名——不承诺防绕过）
- **所有 git push 尝试均落 audit**（含命令原文、放行/拒绝结果）——问责靠审计回溯
- 标题/契约措辞：「Git 上传流程关卡（护栏+审计）」，不给错误安全预期

### 5. [gitGate 配置关系] 新开关 gitPushGate
**落实**：core.js 既有 `gitGate:false`（早前"评审前禁 git 提交"）——**保留不动**（语义不同：gitGate=提审前禁 commit；gitPushGate=push 前测试先行）。新增 **`gitPushGate`** 默认 false + **cordis.patch.yml 显式 `gitPushGate: true`**（部署即启用）。

### 6. [收录类判定] git diff + fail-closed 降级
**落实**：
```bash
changed = execSync('git diff --name-only @{upstream}...HEAD -- data/plugins/')
# upstream 不可解析（无 upstream/多 remote）→ 按收录类处理（fail-closed：要求 gate-precheck）
```
判定命令 + 降级语义如上（upstream 缺失按收录类 = 更严）。
