## 背景与问题

git-submit-practice skill（六章：测试先行/自查/gate 处理/打回跟进/台账）**只是文档**——会话不加载 skill 即可绕过（与 036 复用评估当初同型）。用户要求：**Git 上传/修改的入口强制化，每个会话不可绕开**。

## 方案：Git 提交关卡（挂 tools/execute bash 拦截）

### 1. push 入口拦截（核心）

dsh-design-review 扩展 tools/execute 拦截 **bash 命令**：
- 识别 `git push`（对外发布入口；commit 是本地动作不拦，push 前必须已满足流程）
- **前置条件检查**（基于 audit 记录的会话状态）：
  - a. **测试先行**：本会话近 30 分钟内跑过测试套件（`node --test` / `python3 *test*.py`——audit action 含 `test-run` 的记录）
  - b. **本地 gate 预检**（收录类 push：目标分支含 `data/plugins/` 变更时）：近 30 分钟内跑过 `check-submission.mjs`（audit `gate-precheck`）
- **不满足 → 拒绝执行** + 明确提示：
  ```
  ⚠️ Git push 被拦：测试先行未满足（近 30 分钟无测试记录）。
  请按 git-submit-practice 流程：① node --test / python3 test 全绿
  ② 收录类先跑本地 gate 预检（check-submission.mjs）③ 再 push。
  ```

### 2. 测试动作登记

- 拦截器识别 `node --test` / `python3 *test*.py` 执行 → audit 记录 `{action: 'test-run', ts}`（30 分钟窗口）
- 识别 `check-submission.mjs` → audit `{action: 'gate-precheck', ts}`

### 3. 跳过/豁免路径（防误伤）

- 白名单：本地分支内 commit（不拦）；非 GitHub 的 push（如本地裸仓库）不拦
- 紧急热修：支持 `git push --no-verify`？——**不允许**（与测试先行冲突）；紧急场景走人工审批（approval 链已有）
- 显式豁免：用户手动在 GUI 批准（approval/request 通道）

### 4. 契约条款「Git 提交规范」（四·十二）

- 所有会话 Git push（GitHub 外发）必须满足：测试先行 + （收录类）本地 gate 预检
- 与 skill 联动：关卡提示指向 git-submit-practice；台账/成功率统计继续

## 接口与兼容性

- tools/execute 扩展（bash 命令识别 git push/node --test/check-submission）——不改变既有 write/edit 拦截
- 30min 窗口为默认（可配置）
- 会话审计（design-review.log）已是状态源——无新存储

## 安全

- 无新权限；拦截 = 拒绝 + 提示（非静默）；豁免走人工审批（fail-closed 语义沿用）

## 测试方案

- T1：跑测试后 30min 内 git push → 放行
- T2：无测试记录 git push → 拒绝 + 提示
- T3：收录类（data/plugins 变更）无 gate-precheck → 拒绝
- T4：跑过 gate-precheck → 放行
- T5：本地 commit（非 push）→ 不拦
- T6：测试记录超 30min → 拒绝

## 风险与回滚

- 风险：误拦正常 push → 白名单/豁免/审批兜底；测试登记漏检 → 提示引导重跑
- 回滚：移除拦截分支（单函数）
