# 20260901-015 方案 A：设计文档识别扩展到 skill 开发路径（Mini 保养教训）

- requestId: 20260901-015
- 类型: design（用户确认方案 A：强制关卡覆盖 skill 开发路径）

## 背景与问题

Mini 保养会话开发 SKILL.md（车辆保养提醒 skill）时**未做复用评估**（未查 Git/本地成熟方案）——agent 事后承认"我漏了这一步"。根因：036 复用评估关卡只挂在"设计文档提审"路径（`isDesignDoc` 识别 `*.design.md`/`DESIGN.md`/`PROPOSAL.md` 或设计关键词），**skill 开发写入不触发** → 三查沦为自觉行为。

## 复用评估

- 本地 CAPABILITY-INDEX：**dsh-design-review 插件自身扩展**（isDesignDoc 模式扩展，非新造）
- 外部收录（awesome）：dsh-tidewatch 类调度插件可参考（GitHub 检索：KhalilYamber/dsh-tidewatch——时段调度工具，与本次时段纪律相关，非直接复用）
- GitHub 借鉴：无直接同型方案（skill 开发关卡是 DSH 特有治理需求）

## 方案（A）

**`isDesignDoc` 识别扩展**——以下写入也触发 auto-submit（复用评估 + 模板关卡）：
1. 文件名匹配：`SKILL.md`（任意深度）、`skills/*/SKILL.md`、`*.skill.md`
2. 路径匹配：路径含 `/skills/` 且文件名含 `skill`（如 `skills/vehicle-maintenance/` 目录下的文档写入）
3. 内容启发：前 40 行含 `skill` 元数据块（`name:`/`description:` YAML frontmatter）的 `.md`

实现：
- `core.js`：`isDesignDoc` 增加上述模式（纯函数，可单测）
- `index.js`：auto-submit 逻辑不变（识别后走 submit → 复用评估 + 模板关卡 → 拒绝时 deliver 原因）
- 注意：SKILL.md 写入的 auto-submit 会拦住**所有会话**的 skill 开发（含本次会话）——符合强制关卡语义（006 lesson 已在同类路径生效）

## 接口与兼容性

- `isDesignDoc` 返回语义不变（true/false），仅扩展匹配面
- 现有设计文档路径不受影响；新增 skill 路径识别
- 潜在噪音：非设计类 skill 文档（如纯配置说明）也会触发——advisory 模式（mode=advisory）下仅通知不阻塞；mandatory 模式拒绝提审

## 安全

- 无新权限；关卡逻辑复用（fail-closed 已加固，009 lesson）
- 拒绝路径 deliver 原因（不静默，003 已实现）
