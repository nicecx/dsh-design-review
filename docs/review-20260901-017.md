## 方案（016 五意见逐条落实）

### 1. [核心·门禁语义] → 方案 (c)：skill 类型独立分支
**落实**：
- `submit()` 新增 `type === 'skill'` 分支：
  - **只跑 `checkReuseSection`**（要求 SKILL.md 内嵌「## 复用评估」节含三查引用，或「无复用」逃逸声明——语义：skill 开发前必须做三查并在文件内留痕）
  - **跳过 `checkTemplateSections`**（skill 文件不是 7 章设计文档，模板检查不适用）
- 拒绝时返回明确提示（`skill 提审被拒：复用评估缺失……`）
- 选择理由：SKILL.md 内嵌复用评估节（轻量一节）比"先交独立 design doc"流程轻（(b)），也不污染 skill 主体结构（(a) 的"节"仅一节且语义贴合）

### 2. [测试缺口] → 补门禁端到端集成用例
**落实**（test/index.test.js 新增）：
- I1：skill 文件含「## 复用评估」节 + 三查引用 → submit 通过（type=skill 分支）
- I2：skill 文件无复用评估节 → submit 拒绝（note 含"复用评估"）
- I3：skill 文件含「无复用」逃逸 → 通过
- I4：design 文件仍走完整双关卡（回归：缺章被拒）

### 3. [模式冗余] → 删除 `skills/*/SKILL.md`
**落实**：保留「文件名 = SKILL.md（任意深度）」+「路径含 /skills/ 且文件名含 skill」两条；`skills/*/SKILL.md` 是前者子集，删除。

### 4. [弱信号] → 收紧 frontmatter 规则
**落实**：删除「前 40 行 name:/description: frontmatter」弱信号（误触发高）；识别收紧为：
- 文件名恰为 `SKILL.md`（任意深度）
- 或 路径含 `/skills/` 且文件名以 `.skill.md` 结尾
- 误触发评估：普通 .md 文档（README/notes）不匹配上述两条；设计文档路径（*.design.md）走既有分支不受影响

### 5. [配置落点] → 硬编码 isDesignDoc（治理语义，不做配置化）
**落实**：skill 识别规则硬编码进 `isDesignDoc`（与 `*.design.md` 同层级），不进 defaultConfig——理由：skill 识别是治理强制语义（非用户可调参数），且避免 validateConfig/patterns/keywords 复杂化。文档注明"如未来需可配置再迁移"。
